# E-Commerce Analytics ETL Pipeline (Capstone Project)
An end-to-end data engineering pipeline designed to extract scattered, raw e-commerce data from the Olist Brazilian E-Commerce Dataset, clean and transform it into a structured star schema, and load it into a centralized PostgreSQL data warehouse for analytical reporting.

## Project Overview
This project addresses the challenges of dealing with fragmented retail data. It automates the process of gathering raw datasets (orders, items, customers, products, sellers, payments, reviews, and geolocation) and building a reliable, repeatable ETL pipeline that ensures data quality, consistency, and clean structure for business intelligence teams.

### Tech Stack
- **Language:** Python 3.10+
- **Data Manipulation:** `pandas` (v2.2.2)
- **Database Connection:** `SQLAlchemy` (v2.0.35) & `psycopg2-binary` (v2.9.9)
- **Environment Management:** `python-dotenv` (v1.0.1)
- **Formatting & Reports:** `tabulate` (v0.9.0)
- **Containerization:** Docker (PostgreSQL 15-alpine instance)

## Current Status: Week 1 Completed (Extract Layer)
The first milestone of the project has been successfully built and executed end-to-end:
*   **Infrastructure Setup:** Spun up a lightweight PostgreSQL 15 database instance using a Docker container, isolating storage with managed volumes.
*   **Strict Ingestion Layer (`extract.py`):** Configured a centralized `SCHEMA` mapping with explicit data types (like setting zip codes and IDs as `string`) to prevent typical pandas parsing issues.
*   **Automated Data Profiling:** Implemented profiling algorithms that automatically calculate row counts, exact row duplicates, and specific missing value percentages, saving them directly into a clean Markdown report (`raw_data_profile_report.md`).
*   **Staging Load Automation (`run_extract.py`):** Developed an end-to-end runner script that automatically creates a secure staging environment (`staging` schema), streams all 9 raw CSV files, chunks them in batches of 10,000 records, and safely loads them into the staging schema with robust exception logging.

## Getting Started

### 1. Prerequisites
Make sure you have **Python 3.10+** and **Docker Desktop** installed on your system.

### 2. Infrastructure Setup (Database)
Create a `.env` file in the root folder with your database credentials:
```env
DB_USER=your_username
DB_PASSWORD=your_password
DB_NAME=olist_db
DB_HOST=localhost
DB_PORT=5433
```
Launch the staging database container using Docker:
```bash
docker compose up -d
```

### 3. Installation & Setup
Set up your isolated Python environment and install the required dependencies:
```bash
python -m venv venv
source venv\Scripts\activate
pip install -r requirements.txt
```
### 4. Running the Extraction Pipeline
To run the extraction, generate profiling metrics, and stream the data into the staging database:
```bash
python run_extract.py
```

*You can monitor execution logs under `logs/extract_pipeline_logs.log`, `raw_data_profile_report.md` for the raw data profiling results, and verify the incoming tables inside your database container using pgAdmin.*
